### deploy-examples-atproto-market

- intent: "" -> "This context exists to pin down the deploy/examples/atproto/market example as an executable specification of what the kcp deno runtime must support: peer services that reach each other only by cluster-local name over TLS, with identity and certificates supplied from outside the pod. It is the reference topology that exercises workspace creation, per-workspace API bindings, per-workspace RBAC, per-workspace OpenBao authority selection, the provider's virtual DNS table and shim, and the TLS leaf injection path, so that a regression in any of those surfaces shows up as a failing verifier pod rather than as an untested assumption in the provider. The example also carries a live acceptance script, so that it is proven by bringing the whole topology up and reaching it, not only by decoding its manifests and fitting them to their schemas. Two properties of the provider virtual DNS shape the manifests: a workload address table is written once at pod start, so a consumer that starts before its producer cannot reach it by cluster-local name, and WebSocket construction cannot fall back to discovery at all. The PDS crawler therefore points at the relay listener address, which needs no table lookup, while the relay reaches the PDS by the cluster-local name its own later start puts in the table."
- added `r.acceptance-survives-a-stalled-provider` (MUST): "The live acceptance must survive a provider that comes up, logs that it is waiting for its APIExport virtual workspace endpoints, and then reconciles nothing: every object apply.sh applies stays without a status and apply.sh fails on its first wait. After the provider is started and apply.sh returns, the acceptance must detect that state within a bounded window - no OpenBao object in any workspace carries status.ready true and no DenoPod exists in any workspace - and, when no workload exists yet, stop the provider, start it again, and run apply.sh again. It must make at least two and at most three attempts, print which attempt it is on, and record each attempt's apply.sh exit code. It must never restart the provider once a DenoPod exists, because the workloads are children of the provider and stopping it would orphan them."
- added `r.acceptance-trap-stops-workloads-first` (MUST): "The live acceptance's EXIT trap must stop the workloads before it stops the provider that owns them. The DenoPod processes are children of the provider, so killing the provider orphans them and they keep holding the fixed host ports 2583 to 2587 of the example, which makes the next run on the same machine unable to bind them. The trap therefore deletes every DenoPod in every workspace through kcp first, waits, bounded, for the objects to disappear (the denopod.deno.computer/run finalizer is what stops each process, and it only runs while the provider is up), and only then stops the provider, OpenBao and kcp and removes ACCEPT_ROOT. It must not stop a process it did not start, and it must do this whether the checks passed or failed."
- added `r.apply-includes-bob-and-bidder` (MUST): "apply.sh names the workspaces global relay alice bob, requires atproto-market/hono-bidder as well as hono-plc, hono-atproto-relay and hono-pds in its preflight check, generates a PDS key for bob and a key for the bidder, each distinct from alice's and each overridable by BOB_PDS_PRIVATE_KEY_HEX and BIDDER_PRIVATE_KEY_HEX, substitutes them into the manifests, applies bob's OpenBao authority with the other authorities, applies bob's PDS manifest before the bidder manifest, and reports the phase and readiness of both pds and bidder in its final summary."
- added `r.four-workspaces-at-root` (MUST): "The example creates exactly the four workspaces global, relay, alice and bob, each with spec.type.name denoruntime and spec.type.path root."
- added `r.live-acceptance-script` (MUST): "The example's live acceptance brings the whole market up in a throwaway state directory and exits non-zero unless every workload is up and reachable. It is bash with set -euo pipefail; ACCEPT_ROOT (default a fresh mktemp -d) is the one directory it owns, and an EXIT trap stops everything it started and removes that directory, never stopping or touching a kcp, kine or OpenBao it did not start. It asks the kernel for three free 127.0.0.1 ports, for kcp, kine and OpenBao, instead of pinning any, so it cannot collide with another instance on the machine. It starts kcp with ROOT under ACCEPT_ROOT and KCP_SECURE_PORT and KINE_ENDPOINT set to two of those ports through deploy/start-kcp.sh, installs the provider through deploy/install-provider.sh, builds ./cmd/deno-kcp-provider into ACCEPT_ROOT, starts OpenBao with OPENBAO_DIR under ACCEPT_ROOT and OPENBAO_LISTEN on the third port through deploy/start-openbao.sh, and runs the provider with --kubeconfig, --openbao-addr, --openbao-token root and RUNS_DIR under ACCEPT_ROOT. It then runs the example's apply.sh with ORG_ROOT the repository parent, KUBECONFIG the kcp admin kubeconfig, the same OPENBAO_LISTEN, START_OPENBAO=0, a bounded WAIT_SECONDS, and the key files under ACCEPT_ROOT. When apply.sh returns, whether it succeeded or not, it reads every DenoPod from kcp with kubectl and prints one line per check with its result and the decisive evidence: apply.sh exited 0; DenoPod plc in root:global, relay in root:relay, pds in root:alice, pds in root:bob and bidder in root:bob each reached phase Running and report ready true; DenoPod verifier in root:alice reached the terminal phase Succeeded; bob's pds answers on its own name, which the provider proves with its readiness probe through the shim and the host proves by fetching the same path from outside with curl against the host port; the bidder answers on its cluster-local name and on its host port. The host check names the scheme the listener actually speaks: the bob PDS serves TLS because its supervisor writes the injected leaf and appends the TLS flags, so its host check is https, and the bidder serves plain HTTP because its supervisor must not append those flags, so its host check is http; the provider's readiness probe is the one that does not care, because it tries https and then http. It prints a final table naming every check and its result, prints the tail of the provider log and the status of the failing pod when a check fails, and exits 0 only when every check passed."
